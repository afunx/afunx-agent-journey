## 我现在的理解

- Agent 循环（用自己的话）：
  Observation（感知到的信息）→ Think / Plan（LLM 决策）→ 选择工具并 Action → 环境变化 → 新的 Observation → ……
  遇到 `Finish` 或达到最大轮数则结束。
- 最初的 `user_prompt` 也可以看成第一次 Observation，用来启动循环；之后的 Observation 主要是工具返回结果。
- LLM 负责决策（调哪个工具，或是否结束），不是一次生成最终答案。所以带工具的对话往往会多轮：Action → Observation → 更新历史 → 再问 LLM。
- 多轮后上下文会不断叠加，token 也会增加。1.3 Demo 把历史都拼进下一轮的 `user` 里，就是这种朴素实现。
- OpenAI 的 `messages` 里：`system` 放角色和规矩（含可用工具、输出格式）；`user` 放当前任务和全部历史（含 LLM 输出与 Observation）。
